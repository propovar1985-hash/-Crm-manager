# MASTER AI — бесплатное облачное внедрение

## Цель
Добавить в существующую CRM «Мастер мебельщик» облачного AI-помощника, доступного из iPhone, iPad и браузера компьютера, без обязательных платных API и подписок.

## Текущее состояние репозитория
- Frontend: один основной `index.html` и отдельные JS-модули.
- Supabase URL: существующий проект `zxgkodaeynzcprhnymee`.
- Авторизация: Supabase Auth.
- Существующая серверная функция: `supabase/functions/super-handler/index.ts` (в частности, интеграция Яндекс Диска).
- Основные разделы, объявленные в приложении: обзор, клиенты, воронка продаж, заказы, календарь, замеры и проекты, расчёты, поставщики, производство, сотрудники, настройки.
- Не изменять и не заменять `super-handler`; AI — отдельная функция.

## Выбранная бесплатная архитектура
1. Интерфейс AI в CRM (адаптивный чат, единый для телефона и компьютера).
2. Отдельная Supabase Edge Function `master-ai` — проверяет Supabase-сессию и является единственным посредником между браузером и моделью.
3. Cloudflare Workers AI, модель `@cf/zai-org/glm-4.7-flash`, через REST API.
4. Секреты Cloudflare хранятся только в Supabase Function Secrets:
   - `CLOUDFLARE_ACCOUNT_ID`
   - `CLOUDFLARE_API_TOKEN`
5. В браузере не хранить Cloudflare token, service-role key или другие секреты.

Cloudflare Workers AI публикует бесплатную квоту 10,000 Neurons в сутки на Workers Free. При исчерпании квоты запросы должны завершаться понятным сообщением; не подключать платный план и не включать автоматические платные списания. Квоты и список моделей могут меняться.
Supabase Free имеет лимиты, включая 500,000 вызовов Edge Functions, 500 MB базы, 5 GB egress; бесплатные проекты могут приостанавливаться после недели бездействия. Не обещать безусловную бесперебойность.

## Безопасность
- Каждый запрос требует действующей Supabase Auth-сессии.
- Секреты провайдера доступны только на сервере.
- На первом этапе AI только отвечает на общие вопросы и не имеет доступа к данным CRM.
- Следующий этап: строго ограниченные read-only инструменты для каждого модуля; данные выбираются сервером по разрешённым полям и только в рамках текущего пользователя.
- Запись/изменение данных — отдельные серверные действия с явным подтверждением пользователя.
- Не передавать модели service-role key, пароли, токены интеграций, полные клиентские карточки или ненужные персональные данные.
- Не разрешать модели генерировать SQL, выполнять произвольные запросы, вызывать произвольные URL или менять базу напрямую.
- Все расчёты размеров, раскроя, кромки и себестоимости остаются детерминированными программными алгоритмами; AI может запускать их через проверенные функции и объяснять результат, но не подменяет их догадками.

## Этапы реализации
### A. Основа (эта ветка)
- Изолированная Edge Function `master-ai` с проверкой авторизации.
- Запросы к бесплатной модели Cloudflare.
- Ограничение размера истории и длины сообщения.
- Только чат без доступа к CRM-данным и без операций записи.
- Документация по настройке секретов и публикации функции.

### B. Встраивание интерфейса
- Добавить пункт «MASTER AI» и адаптивное окно чата в существующий интерфейс.
- Получать access token через существующий `db.auth.getSession()`.
- Отправлять сообщения только на `/functions/v1/master-ai`.
- Не менять существующие модули и обработчики.

### C. Подключение всех модулей (после инвентаризации реальной схемы БД)
- Обзор: агрегаты и состояние работы.
- Клиенты и воронка: поиск, история, статус контакта.
- Заказы: этапы, суммы и сроки.
- Календарь, замеры и проекты: события и незавершённые действия.
- Расчёты: запуск существующих расчётных функций и проверка входных параметров.
- Поставщики и закупки: группировка спецификаций по поставщикам и заказам.
- Производство и монтаж: этапы, комплектность, задержки.
- Сотрудники и настройки: только разрешённые текущему пользователю данные; критичные настройки не менять автоматически.

### D. Подтверждённые действия
- Сначала показывать проект действия.
- Запрашивать подтверждение.
- Проверять права и повторно валидировать входные данные на сервере.
- Записывать аудит: пользователь, действие, объект, время и результат.
- Запретить удаление заказов, изменение договорных сумм и финансовые операции без отдельного явного подтверждения.

## Проверки перед публикацией
- Авторизованный запрос проходит; запрос без сессии получает 401.
- Неавторизованный Origin отклоняется.
- Невалидный JSON, слишком длинная история и неизвестная роль отклоняются.
- Ошибка/лимит Cloudflare не вызывает платный fallback.
- Ни один секрет не попадает в клиентский JS, HTML, GitHub или логи.
- Существующие вход, клиенты, заказы, расчёты, поставщики и производство продолжают работать.

## Важно
Ветка не развёрнута в Supabase и не опубликована в GitHub Pages. Для включения Cloudflare AI владелец должен создать бесплатный Cloudflare account/API token и добавить два секрета в Supabase. Подключение к CRM-таблицам начинается только после проверки схемы и политик RLS.
